# fix(chat): 回答里的公式用本地 KaTeX 渲染

v0.2.2 批次（逐项小 PR）第 1 个：问题 2，公式不渲染。不改版本号。

## 问题
对话里模型输出的公式显示成原始 LaTeX，例如 `$p_e = \dfrac{P}{\sqrt{2}}$`。原因是渲染管线（marked + DOMPurify）没有处理数学语法。

## 修复
- **识别公式**：用 remark-math 解析，和追问分支映射（rendered-map）共用同一棵 mdast。支持四种写法：`$…$`、`$$…$$`、`\(…\)`、`\[…\]`。
  - `\(…\)` 和 `\[…\]` 会先改写成 `$$…$$`。改写前后长度相同，所有源 offset 不变。代码片段和代码块里的不改写。
- **显示方式**：单独成段的 `$$…$$` 和 `\[…\]` 按块级公式显示，其余按行内显示。
- **渲染流程**：
  1. 先把公式换成私有区字符包起来的占位符；
  2. marked 解析，DOMPurify 净化（规则不变）；
  3. 再把占位符换成 KaTeX 的输出。
- **KaTeX 设置**：`trust: false`，所以 `\href`、`\url`、`\html*` 不会生成链接或 HTML。`throwOnError: false`，写错的公式显示源码，颜色用 `var(--danger)`。
- **本地资源**：KaTeX 的 CSS 和字体由 Vite 打进 renderer 资源，不从 CDN 加载。CSP 原样不动：`default-src 'self'`，字体走 'self'。
- **长公式**：块级公式在窄面板里可以横向滚动。
- **追问分支**：rendered-map 处理 `inlineMath` 和 `math` 节点，把公式的 TeX 源码当作它的可见字符，逐字映射回源 offset（和代码片段一样，不含 `$` 定界符）。
  - 渲染端把每个 KaTeX 元素当作一个整体，从 MathML 的 TeX annotation 读回源码，选区碰到公式就整个算进去。
  - 公式前后、跨过公式、从公式本身发起的选区都能对齐。锚点是源切片（含 LaTeX），展示和发送的文字里，公式写成 `$tex$` 或 `$$tex$$`。
  - 文字和 TeX 对不上时仍然返回 null，绝不返回错位的切片。

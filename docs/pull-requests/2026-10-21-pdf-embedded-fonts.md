# fix(pdf): PDF 选区重影、条纹和行间空隙（嵌入字体样例）

v0.2.2 批次，问题 5 的后续（测试员在嵌入字体的 PDF 上复测 #63 未通过）。不改版本号。

**结论：选区重影已修复，嵌入字体时字位置偏移是已知问题，v0.2.3 修。** 问题 5 保持打开。

## 问题（测试员复测，嵌入字体 + 两端对齐的 PDF）
1. 重影：选中后文字层的字形以系统高亮色显示出来，和画布上的字形错开，看起来是两层字。
2. 条纹：相邻 span 重叠的地方高亮叠了两次，出现深色竖条。
3. 行间空隙：多行选区每行之间露出一条白色页面。
4. 字位置偏移：文字层的单词和画布上的单词左右错开几个像素。

## 修复（只作用于 `.pdf-text`，应用其他地方仍是 #44 的系统默认高亮）
- **重影、条纹**：按 pdf.js 上游查看器的做法：
  - 文字层字形始终透明（选中时也是）；
  - 整个文字层 `opacity: 0.25`，`::selection` 用实色 `var(--accent)`；
  - 透明度放在整层而不是每个 span 上，重叠的 span 只合成一次，所以没有条纹；
  - 不用 mix-blend-mode。
  - 文字层里的标记底色相应调到 48%，乘上 25% 后和其他格式的 12% 一致。
- **行间空隙**：文字层渲染完后，给每个 span 设置行高，等于到下一行的距离（只在同一栏、同一段内），字形位置不变；上标这类小字号 span 使用同一行的高度，选区里不留洞。
- **#44 测试调整**：`marks-followup.test.ts` 原来断言 CSS 里没有任何 `::selection`，按架构设计师的裁定改为「所有 `::selection` 选择器都以 `.pdf-text` 开头」。应用其他地方仍然不允许自定义选区。

## 已知问题：嵌入字体时字位置偏移（v0.2.3）
限时探查没有达到要求（嵌入字体样例上 ≥ 90% 的单词偏移在 1px 内），所以本 PR 不包含这部分改动。

| 缩放 | 1px 内的单词占比（本 PR） | 95% 分位偏移 | 最大偏移 |
|---|---|---|---|
| 100% | 0.371 | 5px | 6px |
| 125% | 0.444 | 7px | 8px |
| 150% | 0.258 | 8px | 9px |
| 200% | 0.292 | 11px | 12px |

（Linux 本地，178 个单词；CI 上每个平台的数据写在 `pdf-embedded-drift-<平台>.json`。修复前 100% 为 0.483，150% 为 0.298，其余相同；差异来自行高调整后透明字形的亚像素位置变化，看不见。）

探查结果：
- 用嵌入字体的 FontFace 渲染文字层：0.534 / 0.404 / 0.376 / 0.011；
- 再用词距代替 scaleX 做两端对齐：0.646 / 0.461 / 0.522 / 0.011。
- 原因：LibreOffice 用 TJ 位移做字距调整，pdf.js 的 textContent 每行只有一项，拿不到单字位置；嵌入字体转换后的字宽也和原字体差约 1.2%。200% 时还有约 3px 的纵向偏差。

这两种方法风险大、收益不够，都没有提交，详细记录在工作日志里。

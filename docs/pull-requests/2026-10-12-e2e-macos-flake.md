# PR：test(e2e): 修复笔记 id 全是数字时 frontmatter 断言随机失败

- **日期：** 2026-10-12 / **分支：** `test/e2e-macos-flake` → `main` / **基线 commit：** `41c3898` / **相关记录：** [工作日志](../work-logs/2026-10-12-e2e-macos-flake.md)

## 关联
修 #28、#31 和 main run 38266937688 上 macOS e2e 的随机失败。

## 改了什么
- **根因（测试问题，不是产品 bug）：** 笔记 id 是 8 位十六进制，大约 2.3% 的概率全是数字。YAML 会把它写成 `id: "37259515"`，而 e2e 的正则 `id: [\\w-]+` 不接受引号。三次失败收到的都是这种情况。产品读回来是正确的。
- 后面几个用例超时，是因为重试时只重跑失败的那个用例，但所有用例共用一个应用，重启后工作区是空的。
- `smoke.spec.ts`：正则同时接受两种写法；文件设为 `serial`，前面的用例失败就跳过后面的，CI 重试时整个文件重跑。
- `notes.test.ts`：新增 4 个用例，用固定的数字形 id（`37259515`、`00000001`、`1234e567`、`12345678`）验证写入加引号、读回是字符串、`list` 正常。

# ⑥ 分支界面：平级回答、‹ n/m › 切换、从任意消息分支

版本：保持 0.1.1，不升。基于 main（f34da03），已合入 main（#40 5b43d8c、#41 f2204b0）。

## 做了什么
- **存储**：沿用 #23 已有的 `parent_id` 和 `branch_origin`，不改表结构，不加 migration。新增的查询都放在 core 的 `conversations/tree.ts` 里，是纯函数：
  - `siblingsOf`：同一位置的几条平级消息，排除追问分支。
  - `latestLeaf`：从某条消息往下，每层都选最新的一条，找到末端。
  - `defaultLeaf`：打开对话时默认显示到哪一条。
  - `branchesFrom`：某条回答派生出的分支。
- **重新生成**：不再删除旧回答，新回答作为平级回答，和旧回答挂在同一个问题下。#23 时重新生成会通过 ON DELETE CASCADE 连带删掉从旧回答派生的分支，现在这些分支都保留。原来的 `it.fails` 已改成普通 `it`。
- **切换器**：同一位置有多条消息时，左下角显示「‹ 2/3 ›」。字号 12px，用 `--muted`；箭头按钮 20×20、圆角 6px，悬停时用 `--hover`，到头的箭头置灰。快捷键 ⌥←/⌥→（Windows 上是 Alt+←/→）。默认显示最新一条。切换后只替换这条及它下面的内容，有 150ms 淡入，开启 `prefers-reduced-motion` 时不做动画。
- **从任意消息分支**：每条消息悬停时有「从这里分支」。
  - 在回答上点：之后的问题会接在这条回答下面，作为一个新分支。
  - 在问题上点：用新问题替换这一问，新问题和原问题平级，都在切换器里。第一条问题也可以这样替换。
- **追问分支**（设计稿 v0.2）：在 AI 回答里选中文字，会弹出「追问分支」。发送后写入 `branch_origin`，记录选中文字在原回答 markdown 里的位置。
- **面包屑和分支入口**：对话顶部有 40px 高的面包屑，显示「主线 › 「引文」」，每一级都能点。「分支树」按钮弹出 320px 宽的浮层，用缩进树显示所有分支，当前节点高亮。回答末尾有「⑂ n 个分支」chip，只统计当前显示的这条回答，点开后能跳到对应分支。
- **为什么 main 也改了一点**：只靠渲染进程做不到，所以 main 有以下最小改动：
  - `TaskRequest` 新增 `parentId` 和 `branch` 两个字段。main 会校验这些 id 都属于当前对话、分支只能从 AI 回答派生、引文和原文位置对得上。
  - 新增只读 IPC `conversations:tree`。
  - 新消息的时间戳保证严格递增，这样同一毫秒里生成的平级回答也能按创建顺序排列。
  - 删掉了 `dropTrailingAssistant`，没有改表结构。
  - 渲染进程只从 `@point/core/tree` 引入树相关的纯函数，因为 core 的总入口会带上 Node 模块，渲染进程加载不了。

## 测试
- core `tree.test.ts`：平级消息的顺序、排除追问分支、`latestLeaf` 和 `defaultLeaf` 的结果、切换后显示的是那条分支下的内容、分支计数、数据有环时能正常结束。
- main：
  - 新增 `branch-ui.test.ts`：带 `parentId` 的重新生成会生成平级回答，并保留分支；带 `parentId` 的追问会接在当前显示的末端下面；`parentId: null` 会新增一条平级的首问；来自别的对话的 id、从问题派生的分支、对不上的引文、越界的位置都会被拒绝。
  - `branches-extra` 的 `it.fails` 改成了普通 `it`。
  - `services`：重新生成那条测试改为断言旧回答保留、新回答是平级的。
- e2e 新增一个用例：重新生成后显示 2/2；先追问，再切到 1/2，追问消失；Alt+→ 切回来，追问又出现；在问题上点「从这里分支」后，问题出现 2/2；在回答里选中文字发起追问分支，面包屑出现对应一级；点「主线」回到主线，再从「⑂ 1 个分支」进入分支。原来截图用例里给 main 打的桩补上了 `conversations:tree`。
- lint、typecheck 退出码都是 0。core 148 项通过；main 616 项通过、4 项跳过；build 通过；e2e 14 项通过、1 项跳过（原来就跳过的）。

# fix(ui): 工具条盖住选区外正文时翻到下方

#81 第一项。不改版本号。行首死点和拖过文档末尾另开 PR。

## 行为
- 默认仍在选区首行上方 8px。
- 若这个位置会压到选区外的正文（三击整行时最常见），改放到选区末行下方 8px。
- 翻下去之后如果还会压正文或会出视口，从下方候选往选区推，直到不再与未选正文二维相交，并留在阅读区内（必要时可压在高亮带上）；两边空隙都不够时，停在与未选正文相交面积最小且留在阅读区内的位置。没有传入正文盒子时，原有「上方空间不够才下翻」的行为不变。

## 改动
- `placeBar` 增加可选 `obstacles`；`Reader.measure` 把 `.pdf-line` / `.block` 里位于选区上方或下方的盒子传进去。相邻行盒常有约 2–3px 重叠，`outsideBodyRects` 的容差为 8px，避免把下一行当成同一行丢掉。
- 区域框选工具条的调用未改（不传 obstacles）。

## 验证
- unit：`placeBar` 原有用例保持；新增盖住上方正文则下翻、远处正文不影响、下方正文不影响、下翻后出视口则夹住、下翻后仍压正文则往选区推开、只竖向重叠但横向错开的正文不触发翻面；`outsideBodyRects` 丢掉与选区同一竖向范围的盒子。
- e2e：`pdf-embedded-fonts` 三击中段正文行（hydro-serif “uncertainty of depth…”），工具条不压下一段（“During the last decade…”）也不压选区上方的行；三击第 1 行仍在上方。

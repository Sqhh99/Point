## 改了什么
- 新增 `apps/desktop/test/main/branch-ui-extra.test.ts`，共 20 个用例。
  - 用 spy 包住 `FakeProvider.prototype.chat`，记录每次发给模型的完整消息列表。
- **上下文隔离（优先）**：
  - 切到第 2/3 条回答后追问：发给模型的内容只有根 → 当前这条路径。不含第 1/3、3/3 条回答，不含 1/3 下面的追问，也不含 3/3 派生出的追问分支。
  - 在追问分支里继续问：能看到分支的来源路径，看不到主线在来源之后的内容、同级的其他回答和其他分支。在分支里再选中文字派生嵌套分支时，同样如此。
  - 重新生成：只发送到这个问题为止的路径，不包含这个问题已有的旧回答。
- **重新生成**：
  - 连续重新生成后出现 1/3 到 3/3，按创建顺序排列；旧回答下面的追问和追问分支都保留，`branch_origin` 不变。
  - 在追问分支里重新生成：新回答是分支内的平级回答，面包屑不变。
- **‹ n/m › 切换**：
  - 用和 `AIPanel` 的 `stepSibling` 相同的方式取相邻项：在 1/m 按 ‹、在 m/m 按 › 都不会切换。
  - 切换后显示的是那一条下面自己的内容（`latestLeaf`）；默认显示最新一条。
  - 追问分支不算作平级的另一条。
- **当前选中哪一条不会保存**：重新加载工作区后，树和平级关系完全一致，但默认显示最新一条。这符合设计，这里把它记录下来。
- **从任意消息分支**：
  - 从主线的回答分支：新问题的 `parent_id` 是这条回答，没有写 `branch_origin`。
  - 从主线的问题分支：新问题和原问题平级。
  - 在追问分支里从回答分支：留在分支内，面包屑保留。
  - 嵌套追问分支：`branch_origin` 指向内层回答，分支树里显示为嵌套。
- **#42 新增的 IPC**：
  - 以下请求都会被拒绝，并且什么都不写：`parentId` 来自别的对话、重新生成时的 `parentId` 来自别的对话、`branch.sourceId` 来自别的对话、`parentId` 是不存在的 id。
  - `conversations:tree` 只返回这个对话的消息和分支来源。调用前后三张表的数据完全一样。传入非法或未知的 id 时返回空结果。
  - 冻结时钟后在同一毫秒里连续写入：时间戳严格递增，平级消息的顺序在重新加载后不变。
- **删除和边界情况**：
  - 删除对话后，它的消息和 `branch_origin` 都被清掉，没有遗留的孤儿行。
  - 对已删除的对话传 `parentId` 或重新生成：被拒绝，什么都不写。
  - 重新生成时 `parentId` 指向一条回答：被拒绝。
  - 非「问」的任务类型，或重新生成，和追问分支一起发：被拒绝。

## 发现的问题（产品 bug，已用 it.fails 标出）
- 位置：`apps/desktop/src/renderer/AIPanel.tsx:327`（`forkFrom`）。
- 在问题上点「从这里分支」时，渲染进程发送的是 `parentId = 这个问题的 parentId`。如果这个问题是一个追问分支的首问，它的父消息是来源回答。
- 结果：改问的新问题被存成主线上的一条普通追问。它离开了分支，也不会和原问题一起显示成 2/2，和 #42 记录里说的「新问题和原问题平级，都在切换器里」不一致。
- 已确认：把 `it.fails` 改成 `it` 后，用例失败，报 `expected [ Array(1) ] to deeply equal [ …(2) ]`。
- 修这个问题需要 main 支持「以同样的 span 再派生一条」（例如复用原分支的 `branch_origin`），只改渲染进程不够。

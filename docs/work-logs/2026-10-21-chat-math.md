# 2026-10-21 公式渲染（问题 2）

- 起点：main `cbb8a90`（v0.2.1）。分支 `fix/chat-math-render`。
- 方案选择：renderer 继续用 marked。公式的识别交给 core 里的 remark-math（`mathSpans`），和 rendered-map 用同一个解析，保证「渲染成公式的部分」和「映射表跳过的部分」完全一致。没有在 marked 里另写一套 `$` 的分词规则，避免两边判断不一样。
- `\(…\)` 和 `\[…\]` 用等长改写成 `$$…$$`：remark-math 把 `$$x$$` 当作行内数学，把单独成行的 `$$\n…\n$$` 当作块级数学。代码节点范围内不改写。
- KaTeX 在 DOMPurify **之后**才插入，因为 KaTeX 的版式依赖 `style` 属性，而现有净化规则禁止 `style`，这条规则不放宽。KaTeX 设为 `trust: false`，它的输出里没有链接和脚本。
- 依赖：core 加 `remark-math@6`，desktop（devDependency，打进 renderer）加 `katex@0.16`。字体共 59 个文件（woff2/woff/ttf），Chromium 只会加载 woff2。
- vitest（desktop）给 `@point/core/rendered-map` 加了别名，renderer 的 `math.ts` 可以在 test:main 里直接测。
- 验证：core 203 项，test:main 752 项，e2e 34 项（本地重装了 gnome-keyring），typecheck 和 lint 干净。

## 第二轮（评审意见）
- lockfile：第一次 `pnpm add` 时，sheetjs 的 `resolution` 丢掉了 integrity，现已恢复成和 main 一字不差。之后用 corepack 和 `packageManager` 指定的 pnpm 10.34.6，每次推送前都在本地跑 `pnpm install --frozen-lockfile`。

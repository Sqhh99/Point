# 2026-10-21 窄窗口标题栏和阅读工具栏（fix/titlebar-narrow）

- 从 main 2da2ede 起分支，之后合并了 main 3dce4b1，以及 #68 的 7b9d71c 和 8d11baf。
- **折行原因**：标题栏的按钮可以被压缩、可以换行，工作区名又不让位。Windows 和 macOS 的字体更宽，所以在这两个平台上会折行，Linux 上不会。
- **「打开 ▾」文字行数**：
  - 先把「打开」和「▾」拆成两个 span。▾ 会换用另一种字体，两个文本的 top 不同，#68 的行数计数得到 2。
  - 改回同一个文本节点「打开 ▾」，收起时再单独显示 ▾。
  - 还去掉了 `line-height: 1`，否则文本高度会超过行高，违反 #68 的规则 (a)。
- **窗口按钮被挤压**：440px 时，标题列 40vw 把右侧格子压到 132px，比窗口按钮的 138px 还小。右侧格子改为 `minmax(min-content, 1fr)`。
- **最小宽度**：240 + 360 + 4 + 320 = 924，原来写死的是 900。现在由 `shared/layout-sizes.ts` 计算，renderer 的网格和分隔条夹紧也用这组常量。
- **对话区宽度**：CSS 的 `clamp` 保证渲染出来的宽度正确，JS 的 `clampChatWidth` 保证保存的状态正确（拖动、缩放窗口、开合侧栏时都会夹紧）。
- **阅读工具栏**：在最小宽度时，阅读区格子 360px，减去滚动条后工具栏约 345px，会收到第 4 级（适合宽度和框选都进「⋯」）。文档名的 min-width 设为 0，可以完全让出空间（标题栏里有完整的文件名）。
- xvfb 没有窗口管理器，`maximize()` 不生效，测试改为把窗口设成整个工作区大小。
- 本 PR 截图的文件名用 `tbfix-` 前缀，避免和 #68 写进同一个目录的 `titlebar-*` 重名、互相覆盖。
- 截图对应提交 `7e964e5`。

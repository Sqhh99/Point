# 工程效能

本文是原「运维发布」职责文件（文件名 `release.md` 保留）。

## 职责
- 负责可复用的构建、测试基础设施、公共 CI、开发环境、依赖落地、打包与发布流程。维护两个平台的公共流水线、打包脚本（Windows 用 Inno Setup，macOS 用 dmg）和 `release.yml`，以及发布说明、构建和安装验证证据、回滚办法。
- 功能导致的代码或测试失败由该功能负责人持续修复；流水线本身、运行器、缓存、依赖源、公共脚本和环境故障由你处理。先定位归属，避免多人循环转派。
- 纯软件或依赖版本更新与 mori 协调，指定唯一负责人；你维护公共构建与兼容机制，不另设依赖审批链。
- 没有公共工程工作时，可以接受开发负责人分配的独立功能，按端到端开发标准负责设计、实现、相关测试及 CI 修复，不固定空等发布。

## 不做的事
- 不是每个功能的测试兜底，也不是每个 PR 合并后的必经交接岗。
- 不以审合产品 PR 为主业，也不恢复强制串行交接链。
- 不要求用户审 PR。

## 约束
- 版本号规则 `va.b.c`：a 是大升级或架构调整，b 是较大的功能调整或优化，c 是 bug 修复或小优化；每次发版都要升。（2026-10-12）
- tag 必须是 `v<package.json 里的版本号>`，并与产物一致。（2026-10-12）
- 本轮功能全部合进 main、两个平台 CI/CD 全绿后即可按既有规则发版，不需要再等用户逐步确认。（2026-10-12）本文件不新授予打 tag、公开发布或生产部署的权限，仍按已有授权执行。（2026-11-17）
- 测试用的 tag 不推到公开仓库 Point 上。（2026-10-12）
- 遵守 [README.md](README.md) 中的共同约束。适用的 Windows/macOS 必需 CI、测试、分支保护与仓库合并规则继续有效，不以减少交接为由削弱。（2026-11-17）
- 只在完成、实质阻塞或公共接口/流水线变化时汇报。（2026-11-17）

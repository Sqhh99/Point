# Point 的 bot 分工

Point 由 1 名开发负责人、4 名职责相同的端到端开发（A–D）和 1 名工程效能协作开发。用户不审 PR，只在用完软件后提意见，所以仓库门禁和按规则进行的独立审查是质量的最后保证，不能用减少交接来削弱。

每个角色一个文件，结构相同：**职责**、**不做的事**、**约束**。「约束」一节随项目推进由用户补充，必须遵守；新增约束时在条目后注明日期。旧文件名保留，供既有链接继续使用。

| 角色 | 文件（旧名保留） | 原名称 | 一句话职责 |
|-----|------|------|------------|
| 开发负责人 | [architect.md](architect.md) | 架构设计师 | 验收、共享接口与集成，必要时编码 |
| 端到端开发 A | [implementer.md](implementer.md) | 功能实现 | 同一功能从设计、实现、测试到交付 |
| 端到端开发 B | [ui-designer.md](ui-designer.md) | UI设计员 | 与 A–D 相同，不是固定 UI 席位 |
| 端到端开发 C | [tester.md](tester.md) | 测试员 | 与 A–D 相同，不是固定测试席位 |
| 端到端开发 D | [pr-reviewer.md](pr-reviewer.md) | PR评审员 | 与 A–D 相同，不是常驻评审关卡 |
| 工程效能 | [release.md](release.md) | 运维发布 | 公共构建、CI、依赖、打包与环境；空闲时可承担功能 |

## 协作方式

1. 用户提需求或反馈。开发负责人明确验收条件和共享接口，按可独立交付的功能指定唯一负责人。小改动由一人做完，不必全队启动。
2. 该功能的负责人持续负责局部设计、界面、实现、相关测试、本地验证，以及该功能引起的 CI 失败，直到满足验收条件。不再默认按「架构 → UI → 实现 → 测试 → PR 评审 → 运维」串行交接，也不在每一步等待批准。
3. 开发 A–D 职责相同，模块按任务调整。默认最多 4 名开发并行，全队最多 6 个角色，按任务独立性启用，不必满员。共享接口、公共配置和重叠文件必须有唯一修改负责人。
4. 按风险和仓库规则，由未参与实现的人做独立审查；不绕过 required reviews，不恢复常驻专职评审岗。
5. 工程效能负责公共构建、CI、依赖、打包与环境，不接管每个功能的测试失败。纯依赖更新与 mori 协调，指定唯一负责人，不另设审批链。没有公共工程工作时，工程效能可按端到端标准承担独立功能。
6. 只在完成、实质阻塞或共享约定变化时汇报。失败直达该功能负责人，避免循环派单。
7. 仍按 [project-records](../skills/project-records/SKILL.md) 写记录。文档和设计稿 PR 不升版本；功能和修复 PR 按下面的版本规则升级。

## 共同约束

- 合并门禁：适用的 Windows 和 macOS CI 都须通过；须有有效测试；没有未解决的阻塞讨论；不合草稿 PR；不强推、不绕过分支保护或 required reviews。（2026-10-12，2026-11-17 重申：不因减少交接而削弱）
- 用户不审 PR，不把阅读 PR 当作用户验收；门禁和使用后的意见才是验收依据。（2026-10-12）
- 版本号规则 `va.b.c`：a 是大升级或架构调整，b 是较大的功能调整或优化，c 是 bug 修复或小优化。功能和修复 PR 升版本，同一轮只升一次；文档和设计稿 PR 不升。（2026-10-12）
- 没真正跑过的检查不能报通过。真实设备或安装包验证以任务验收条件为准；默认执行环境是 Linux，没有对应 Windows/macOS 设备时必须如实记录阻塞，不得标为通过。（2026-10-12，2026-11-17 补充）
- 测试不连真实网络、不用真实 API key，用 `POINT_FAKE_LLM` 和 `POINT_USER_DATA`。（2026-10-12）
- 模型 API 统一走 `LLMProvider` 接口；AI 输出的 md 和 mermaid 一律当不可信内容处理。（2026-10-12）
- 数据库表结构变化必须带迁移脚本；跨模块约定（锚点、IPC、模型接口）和 `PRAGMA user_version` 由指定的唯一负责人维护。（2026-10-12）
- 界面只保留一套设计规范：纸面色背景、衬线正文、一种强调蓝、8px 间距网格、圆角 8px；颜色只用 `style.css` 里的变量。使用自定义标题栏，不用 Electron 自带的。布局要精炼，但不能简陋。设计稿放在 `docs/design/<版本>/`，素材放在 `apps/desktop/build/` 或 `docs/assets/`。（2026-10-12）
- 本职责文档不新授予提交、合并、打 tag、公开发布、生产部署或对外发消息的权限，按已有授权执行。当前计划没有 Cloud Agents，不得把它当成可用能力。（2026-11-17）
